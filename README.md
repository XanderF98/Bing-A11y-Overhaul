# Bing Accessibility (A11y) Overhaul

**Technical Project Manager | Microsoft (via Apex Systems)**

> Portfolio repo showcasing execution discipline and visuals for an Accessibility (A11y) initiative on the Bing search platform.

---

## Overview
While supporting the Bing search platform at Microsoft, I led a targeted accessibility (A11y) execution initiative to stabilize release quality, reduce defect intake, and improve compliance across a high‑traffic user experience. The effort focused on addressing fragmented ownership, inconsistent acceptance criteria, and a rapidly growing backlog of accessibility issues that were slowing delivery and increasing operational risk.

## Problem
Accessibility issues were being identified across multiple teams, but no consistent framework existed to ensure issues were prevented, triaged, or resolved efficiently.

**Key challenges included:**
- A backlog of 1,000+ accessibility defects, with inconsistent prioritization
- Undefined acceptance criteria leading to frequent regressions
- Diffuse ownership across product, design, and engineering teams
- Growing operational risk as accessibility defects delayed releases and increased rework

These issues impacted delivery velocity and introduced risk to both customer experience and compliance.

## My Role
As the Technical Project Manager, I was responsible for stabilizing execution across the accessibility pipeline.

**I owned:**
- Delivery cadence and backlog health
- Cross‑team coordination between engineering, design, and QA
- Definition and enforcement of accessibility acceptance criteria
- Risk identification, escalation, and follow‑through
- Executive reporting and progress visibility

I did not own technical design decisions but ensured that decisions were made, documented, and executed consistently.

## Approach
1. **Established Clear Ownership & Intake Control**  
   Partnered with engineering and design leads to define clear ownership boundaries for accessibility issues. New workflows were implemented in Azure DevOps to enforce proper triage, prioritization, and assignment at intake, preventing unbounded backlog growth.

2. **Standardized Accessibility Acceptance Criteria**  
   Worked with UX and accessibility stakeholders to formalize consistent A11y acceptance criteria that applied across features and teams. These criteria were embedded directly into development and review workflows, shifting A11y validation earlier in the SDLC.

3. **Backlog Reduction Through Focused Execution**  
   Led a specialized task force to systematically address the existing defect backlog. Using structured sprint planning and dependency tracking, we prioritized high‑impact issues while eliminating duplicates and stale items that no longer reflected current product behavior.

4. **Execution Visibility & Leadership Reporting**  
   Built dashboards surfacing real‑time metrics including backlog size, intake rate, burn‑down, and release readiness. These dashboards enabled leadership to quickly assess risk and resource needs without interrupting teams.
